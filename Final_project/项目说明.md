## 1. 项目是什么

我们在 **已有 blog 网站** 上，做一个 **AI 阅读助手（Agent）**，帮助读者：

- 在文章库里 **找内容、问问题、看引用**
- 根据阅读记录 **获得推荐和续读建议**
- 按主题 **规划阅读顺序**
- 执行 **阅读清单、评论草稿** 等操作（需用户确认）

**不是** 一个简单的 ChatGPT 聊天框，而是带 **专门工具（tools）** 的 Agent 系统，难度对标课程 Track 1（Factory Co-Pilot）。

## 4. 我们要做的 6 类核心能力

对标 Track 1 的 tool 设计思路，proposal 里承诺的能力如下：

### 4.1 Retrieval & Tracing（检索与溯源）

- 读者提问：「某篇文章讲了什么？」「哪几篇讲过 XX 概念？」
- Agent 从文章库检索，回答时 **附带原文链接/段落引用**
- 事实必须来自 tool 检索，不能靠 LLM 瞎编

### 4.2 Judgement & Discovery（判断与发现）

- 结合 **浏览历史 + 标签 + 文章 metadata** 推荐下一篇
- 发现用户可能遗漏的相关文章
- 登录/打开助手时提示「你上次在读…」「同主题还有…」

### 4.3 Reading Path Planning（阅读路径）

- 用户说「我想学机器学习」→ 返回 **有序阅读列表**
- **第一版**：按 tag/topic **手工配置路径**（后台或 JSON），Agent 负责选取和呈现
- 不追求全自动图谱推理（太复杂，留作加分项）

### 4.4 Proactive Assistance（主动辅助）

- 基于 `BrowsingHistory` 的续读建议
- **v1 不做** 邮件/push 定时提醒（Celery 尚未配置）
- 在 **session 内 / 登录时** 主动提示即可

### 4.5 Confirmed Actions（需确认的操作）

- 加入阅读清单
- 生成评论草稿（用户确认后才真正发布）
- 所有操作 **confirm 前不执行**，执行后 **写 audit log**

### 4.6 Paywall-aware Q&A（付费内容保护）

- 非会员问付费文章细节 → **不泄露正文**，可给摘要或引导订阅
- Eval 里专门测「是否违规泄露付费内容」

```
用户 ←→ 聊天 UI（HTMX）
           ↓
      Agent Orchestrator（LLM 编排，选 tool、组织回答）
           ↓
    ┌──────┼──────┬──────────┬────────────┐
    ↓      ↓      ↓          ↓            ↓
  RAG   关键词   浏览历史   阅读清单    Paywall

    ↓
 向量库（Chroma / pgvector）← 从 Wagtail 文章同步
    ↓

```

## 6. 评估方案（课程重点，不能省）

### 6.1 测试集

至少 **30 道题**，基于真实 blog 文章，每题有 **标准答案**：

| 类型 | 大约题数 | 例子 |
|------|----------|------|
| 事实问答 | 10 | 「总结文章 X」 |
| 跨文章检索 | 5 | 「哪些文章讲过 Y？」 |
| 推荐/路径 | 5 | 「学 XX 先看哪几篇？」 |
| 状态/续读 | 5 | 「我上次读到哪了？」 |
| Action | 5 | 「把这 3 篇加入清单」 |
| 使坏题 | ≥5 | 不存在的文章、模糊问题、付费内容 bait |

### 6.2 Baseline 对比

| 系统 | 说明 |
|------|------|
| Baseline A | 纯 LLM，无检索 |
| Baseline B | 现有 Wagtail 关键词搜索 + LLM 总结 |
| Baseline C | 基础 RAG（向量检索 + LLM，无 tools/个性化/paywall） |
| **Full Agent** | 完整 tool set（我们要 beat C） |

### 6.3 主要指标

- Answer accuracy（答案对不对）
- Citation accuracy（引用是否支持答案）
- Hallucination rate（是否编造文章/内容）
- Refusal accuracy（该拒的是否正确拒绝）
- Paywall leak rate（付费泄露，目标 **0**）
- Recommendation Hit@K
- Unsafe action rate（未 confirm 就执行，目标 **0**）

### 6.4 人工评估

至少 **3 人**（同学即可）：任务完成时间、主观满意度、与 baseline 盲测偏好。

## 11. 常见问题

**Q：这和普通 RAG 聊天机器人有什么区别？**  
A：我们有 **多类 tools**（不只向量检索）、**个性化**（浏览历史）、**paywall 规则**、**需 confirm 的 action**、以及 **baseline 对比 eval**。课程要的是 Agent 系统设计，不是套一个 prompt。

**Q：组员不会 coding 能做什么？**  
A：出题、测系统、打分、写报告、录 demo——这些占最终成绩很大比重，且 eval 设计本身就是课程要求。

**Q：功能做不完怎么办？**  
A：Proposal 承诺的是 **6 类能力**，不是每个细节。Phase 1–2 是必做，路径规划和 proactive 可先做简化版。Eval 和 baseline 不能砍。

**Q：代码在哪？**  
A：`Final_project/blog/`，本地运行见 `blog/scripts/run_local.sh`。
